## Concepts To Preserve

| Concept | How to use it safely |
|---|---|
| Estimation starts by understanding the product boundary | Ask for business goal, bounded context, actors, capabilities, entities, and transactions before sizing. |
| Size and duration are different questions | Route size work to a sizing method first; convert to dates/cost only after validated size and productivity inputs exist. |
| Modified software is not automatically cheaper than new software | Surface comprehension cost for existing code, dependencies, regressions, and refactor scope. |
| Team knowledge changes estimation confidence | Ask for local historical data, implementer input, and technology familiarity. |
| Non-functional requirements affect size and plan | Explicitly ask about performance, security, integrations, AI calls, operations, QA, UAT, infrastructure, and documentation. |
| Single-number estimates hide uncertainty | Require assumptions, range, confidence, and human review before downstream use. |
